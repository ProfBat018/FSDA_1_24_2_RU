# MicroOrm and ORM

`MicroORM` - это Micro Object Relational Mapping. Микро связывние объектов с реляционными данными.
`ORM` - Object Relational Mapping. Связывание объектов с реляционными данными.

После того как мы с вами научились создавать базы данных 
и выполнять SQL запросы, настало время соединить эти знания 
со знаниями прогарммирования. Для того чтобы работать с 
базами данных из C#, нам надо для начала подключиться к базе.

По началу для всего этого использовался `ADO.NET`, который
является самым низкоуровневым способом работы с базами данных.
Но в `.NET` есть более удобные способы как `Entity Framework` и `Dapper`.

Первые 2-3 урока мы будеи работать с `Dapper`.

Давайте разберем в чем разница между `ADO.NET`, 'Dapper' и `Entity Framework`.

## Framework vs Library

Библиотека - это собранный код, который мы можем использовать в нашем проекте.

Фреймворк - это набор библиотек, который определяет структуру нашего проекта.
То есть фреймворк определяет как мы будем писать код, какие библиотеки использовать и т.д.

Если вы используете .NET Core, который является фреймыорком, то он уже определяет что вы 
можете делать и какой набор библиотек вы можете использовать.

## ADO.NET

В случае с ним нам приходиться писать .sql запросы вручную и считывать данные 
с помощью `SqlDataReader`. Это довольно утомительно и неудобно. 
Запись происходит вручную. Есть два способа подключения к базе данных:
1. Connected Mode
2. Disconnected Mode

В первом случае мы постоянно подключены к БД и все запросы как записи так и считывания 
происходят напрямую. 

Во втором случае мы подключаемся к БД, считываем данные и отключаемся. Данные хранятся в 
памяти и мы можем работать с ними. После чего мы можем отправить изменения обратно в БД.

Как вы понимаете у этих методов есть свои плюсы и минусы. Если вы больше считываете,
то нужно использовать Disconnected Mode. Если же вы больше пишите, то Connected Mode.

В нашем предмете вы не будете использовать `ADO.NET` так как он слишком низкоуровневый и больше
не используется в большинстве проектов.

## Dapper

`Dapper` - это микро ORM, в отличии от `ADO.NET`, который просто отправлял запросы с C# в БД,
`Dapper` позволяет нам работать с БД как с объектами. То есть мы можем создавать классы и
связывать их с таблицами в БД. 

## Entity Framework

`Entity Framework` - это ORM, который позволяет нам работать с БД как с объектами. В отличии от 
`Dapper` нам вообще не приходится писать SQL запросы. Все действия проходят через связыание классов, 
LINQ запросы и т.д.

Представьте что вы просто добавляете данные в список и потом делаете `SaveChanges()` и все данные
сохраняются в БД. Более того с помощью утилит вы можете сдублировать вашу БД в классы и наоборот. 
Об этом мы поговорим на следующих уроках.

# Параметризованные запросы

Параметризованные запросы - это запросы, в которых мы можем передавать параметры.

Они нужны для того чтобы избежать SQL инъекций. Такой тип атаки добавляет в запрос SQL код, который
может изменить запрос и выполнить его.

В случае параметра мы можем передать значение, которое будет вставлено в запрос. Таким образом мы
можем избежать SQL инъекций.

```sql
var commandString = "select * from Users where userName = @userName";

using var connection = new SqlConnection(connectionString);
connection.Open();

var user = connection.QuerySingle<User>(commandString, new {userName = "alice_smith"});

Console.WriteLine(user);

```

В примере выше мы видим что вместо значения мы передаем параметр `@userName`. 
Это позволяет нам избежать SQL инъекций. Даже если человек напишет `drop table Users`,
то это не повлияет на наш запрос. Он попытается найти пользователя с именем `drop table Users`.
