## Что такое EF Core ?

EF Core - это ORM (Object-Relational Mapping) фреймворк, который позволяет работать с базами данных, используя объектно-ориентированный подход.

Мы с вами уже работали с Dapper и немного
с ADO.NET, так что нам есть с чем сравнивать. Dapper - помогал нам связывать наши тпблицы с классами, в случае выгрузки данных из БД. ADO.NET - позволял нам работать с БД напрямую, без использования ORM фреймворков и какой-либо привязки.

`EF Core` подразумевает полный отказ от `SQL` кода с помощью `LINQ` запросов.

## Почему его называют Framework ?

Как мы уже знаем, библотека - это набор готовых инструментов который помогает нам в написании логики. Фреймворк - это тоже набор таких инструментов. В свою очередь он может состоять из нескольких библиотек. Но есть большая разница между ними. Фреймворк сковывает нас в рамках своей архитектуры. В связи со своим размером, библиотека просто интегрируется и используется. Фреймворк становиться частью вашего проекта, из-за которого вы можете даже делать изменения.

## Какие преимущества у EF Core ?

Плюсы:

- Простота использования
- Поддержка LINQ
- Нет надобности писать SQL запросы
- Поддержка миграций
- Поддержка множества провайдеров БД
- Очень быстрый, несмотря на то что это ORM
- Много готовых инструментов для работы с БД

Минусы:

- Сложно выучить, в связи с размером
- Большая БД требует особого подхода
- Так как это фреймворк, надо уметь работать с несколькими библиотеками

В общем и целом я не вижу никаких минусов у EF Core. С точки зрения архитектуры мы сами должны решать что стоит использовать в зависимости от масштаба проекта и скорости работы, а не бросать все камни в EF или же Dapper.

## Типы подходов к работе с EF Core

Существует два типа подходов к работе с EF Core:

- Database First
- Code First

### Database First

В таком случае мы сами создаем БД и таблицу, а EF Core на их основе создает классы
и контекст работы с ним.

### Code First

Мы сами описываем классы, и на их основе EF Core создает БД и таблицы.

```bash
    <PackageReference Include="Microsoft.EntityFrameworkCore" Version="9.0.2" />
    <PackageReference Include="Microsoft.EntityFrameworkCore.SqlServer" Version="9.0.2" />
    <PackageReference Include="Microsoft.EntityFrameworkCore.Design" Version="9.0.2" />
    <PackageReference Include="Microsoft.EntityFrameworkCore.Tools" Version="9.0.2" />
```

Первый пакет нужен для того чтобы устновить сам `EF Core`.

Второй пакет нужен для того чтобы установить провайдер для работы с `SQL Server`.

Третий пакет нужен для того чтобы создавать миграции и делать `scaffold`

Четвертый пакет нужен для того чтобы работать в консоли.

## Dotnet EF CLI

Обычно люди использую `Visual Studio` и `Package Manager Console` для того чтобы
запускать команды EF Core. Я ярый сторонник того, чтобы использовать `CLI` (Command Line Interface) для работы с EF Core.

Для того чтобы добавить миграцию, нужно выполнить команду:

```bash
    dotnet ef migrations add <название миграции>
```

Для того чтобы обновить БД, нужно выполнить команду:

```bash
    dotnet ef database update
```

### Правильный выбор объектов, Tolist() и проекция

```csharp
// var fuelTypes = context.FuelTypes.ToList();
//
// foreach(var fuel in fuelTypes)
// {
//     Console.WriteLine(fuel.FuelName);
// }

var fuelTypes = context.FuelTypes;

foreach(var fuel in fuelTypes)
{
    Console.WriteLine(fuel.FuelName);
}


```

В первом случае когда я все беру и делаю `ToList` он сразу же выполняет
запрос `select` в базе данных прямо на той строке где я это написал.

Во втором случае где я не делаю ToList и использую его как `DbSet`, то он делает этот
запрос уже при использовании. В нашем случае это происходит в цикле `foreach`.

Но это могло бы быть в любом месте где эта переменная используется.

```csharp

var petrolCars = context.Cars
    .Include(c => c.FuelType)
    .Where(c => c.FuelType.FuelName == "Petrol");

Console.WriteLine(petrolCars.ToQueryString());

foreach(var car in petrolCars)
{
    Console.WriteLine($"{car.Make} {car.Model} {car.Year} {car.FuelType.FuelName}");
}

```

В данном примере явно видно что смысла в `ToList` совсем нету,
так как он сразу же выполняет запрос и теряет время на преобразование в `List`.

Из-за того что IQueryable это ленивая загрузка, то он не выполняет запрос
пока не станем его использовать. к тому же он имплементриуется от IEnumerable,
что дает нам возможность использовать его в цикле `foreach` и в LINQ запросах.

## Проекция

Пример который я написал в прошлой части выводил следующий `SQL` кода

```sql
SELECT [c].[Id], [c].[CarTypeId], [c].[FuelTypeId], [c].[Make], [c].[Mileage], [c].[Model], [c].[Year], [f].[Id], [f].[FuelName]
FROM [Cars] AS [c]
INNER JOIN [FuelTypes] AS [f] ON [c].[FuelTypeId] = [f].[Id]
WHERE [f].[FuelName] = N'Petrol'

```

Здесь вы можете увидеть колонки которые я не использую в своем `foreach`. Например,
`[c].[CarTypeId]`, `[c].[Mileage]`, `[c].[Model]`, `[c].[Year]`, `[f].[Id]`.

Для того чтобы избежать этого, нужно использовать проекцию.

Слово выглядит сложным, но на самом деле это просто метод `Select`.

## Подгрузка таблиц в EF Core

Для того чтобы сделать `Inner Join` в EF Core, у нас есть три
варианта того как это сделать. В целом все три варианта очень
легкие. Давайте их рассмотрим:

1. Lazy Loading
2. Eager Loading
3. Explicit Loading

### Lazy Loading

Данный тип подгрузки уже не поддерживается по умолчанию в EF Core
так как он требует очень много производительности. Для тестовых
целей мы его включим. Для этого нужно скачать дополнительный
пакет `Microsoft.EntityFrameworkCore.Proxies`.

Также вам придется сделать `virtual` все ваши
навигационные свойства в ваших моделях.

Пример будет в проекте CodeFirst Part7.

### Eager Loading

Или как его еще называют жадная подгрузка. Для того чтобы
сделать жадную подгрузку, нужно использовать метод `Include`.

В отличии от `Lazy Loading`, `Eager Loading` делает запрос
в базу данных сразу же. Он подгрузит все данные которые вы указали.

### Explicit Loading

Данная подгрузка в отличии от жадной подгрузки, делает запрос
в базу данных только тогда когда вы явно этого попросите.

Для того чтобы сделать это, нужно использовать метод `Entry` и
`Collection` или `Reference`.

То есть он сперва подгружает саму строку данных, а потом все то, что вам 
понадобится. 

Метод `Entry` принимает в себя объект, у которого вы хотите
подгрузить данные. Метод `Collection` или `Reference` принимает
в себя название навигационного свойства.

`Collection` нужен для того чтобы подгрузить все элементы в таблице,
а `Reference` для того чтобы подгрузить один элемент.


В случае с `Explicit Loading` и `Eager Loading` нет подхода лучше 
или хуже. Все зависит от вашего проекта и от того какие данные вам
нужны.
