## Что такое FTP ? 

`FTP` (File Transfer Protocol) - это протокол передачи файлов по сети. Он позволяет передавать файлы между компьютерами, используя клиент-серверную архитектуру. `FTP` работает по модели "запрос-ответ", где клиент отправляет запросы на сервер, а сервер отвечает на них. Это протокол `Application Layer`, который работает на портах `20` и `21`. Под капотом он использует `TCP` для передачи данных. 

## Как работает FTP ? 

У него как и у протокола `HTTP` есть 2 режима работы: `Active` и `Passive`. 
В `Active` режиме клиент открывает порт и ждет подключения от сервера. Сервер подключается к клиенту и передает данные. В `Passive` режиме сервер открывает порт и ждет подключения от клиента. Клиент подключается к серверу и передает данные. При этом также у него есть свои методы. Хоть мы и не проходили пока с вами HTPP, я думаю что вы видели или слышали о его методах, таких как `GET`, `POST`, `PUT`, `DELETE` и т.д. У `FTP` также есть свои методы, такие как: 
- ListDirectory - получение списка файлов в директории
- UploadFile - загрузка файла на сервер
- DownloadFile - загрузка файла с сервера 
- DeleteFile - удаление файла с сервера

и так далее. 

При это вам важно понять что, на стороне сервера, `FTP` это всего лишь папка к которой есть общий полностью открытый либо ограниченный доступ. Он может быть защищен паролем, но это не обязательно. 

Хоть этот протокол и устарел, но много где он все еще используется. Программисты его используют для переноса своего проекта на сервер. К примеру вы написали какой-то проект и хотите разместить его на сервере. Для этого вы выбираете хостинг, с поддержкой `FTP`, и загружаете туда свой проект. Как пример могу скзать `MonsterASP.NET` 

Вы можете без проблем в Visaul Studio или в Rider сделаль `Publish` и указать там `FTP` адрес вашего сервера, логин и пароль. После этого вы сможете без проблем загрузить туда свой проект. 

Казало бы что это удобно, но на самом деле это не так. В современном мире есть много других более удобных способов загрузки файлов на сервер. К примерц `Github Actions`, `GitLab CI/CD`, `Azure DevOps` и т.д. Те же самые `GitHub Actions` позволяют вам автоматически загружать ваш проект на сервер, без использования `FTP`. Представьте что вы просто сделали `push` и ваш проект автоматически загружается на сервер. Это намного удобнее чем каждый раз открывать `FTP` клиент и загружать туда свой проект. При чем современные подходы позволяют обновлять приложения без их остановки.

## Разница между FTP и HTTP 

`FTP` и `HTTP` - это два разных протокола, которые используются для передачи данных по сети. Конечно же вы и по `http` можете передавать файлы, но это не его основная задача. По `http` вы также можете скачивать файлы, загружать их. 

# Основные различия между HTTP и FTP

## 1. Назначение
- **HTTP (HyperText Transfer Protocol)** — протокол для передачи веб-страниц, текстов, изображений и других ресурсов через интернет.
- **FTP (File Transfer Protocol)** — специализированный протокол для обмена файлами между компьютерами.

## 2. Способ соединения
- **HTTP** использует одно TCP-соединение на порт **80** (или **443** для HTTPS).
- **FTP** использует два TCP-соединения:
  - **Управляющее соединение** (обычно порт **21**) — для отправки команд и управления сессией.
  - **Данные передаются** через отдельный канал (активный или пассивный режим), порт для данных может быть различным.

## 3. Формат передачи
- **HTTP** передает файлы в виде потока данных с HTTP-заголовками, содержащими метаинформацию:
  - `Content-Type`
  - `Content-Length`
  - и другие заголовки.

- **FTP** использует команды управления и отдельную передачу данных:
  - Передача может быть в **ASCII-режиме** (для текстовых файлов) или в **BINARY-режиме** (для двоичных файлов).

## 4. Скачивание и отправка файлов
- **HTTP**:
  - Скачивание: отправляется запрос `GET`, сервер возвращает файл.
  - Загрузка: используется запрос `POST` или `PUT` (если сервер поддерживает).

- **FTP**:
  - Скачивание: команда `RETR <имя_файла>`, файл передается через канал данных.
  - Загрузка: команда `STOR <имя_файла>`, файл отправляется по отдельному каналу данных.

## 5. Аутентификация
- **HTTP**:
  - Может работать без авторизации или использовать базовую/расширенную аутентификацию.

- **FTP**:
  - Обычно требует логин и пароль.
  - Возможен анонимный доступ (**Anonymous FTP**).

## 6. Безопасность
- **HTTP** передает данные в незашифрованном виде (если не используется HTTPS).
- **FTP** также передает данные и команды в незашифрованном виде (если не используется FTPS или SFTP).

| Безопасность         | HTTPS для шифрования              | FTPS/SFTP для шифрования             |


## Почему он уже устарел ? 

`FTP` считается устаревшим по нескольким причинам: 
1. **Безопасность**: `FTP` передает данные в незашифрованном виде, что делает его уязвимым для атак типа "человек посередине" (MITM). Современные протоколы, такие как `SFTP` и `FTPS`, обеспечивают шифрование данных. 
2. **Совместимость с брандмауэрами**: `FTP` использует динамические порты для передачи данных, что может вызывать проблемы с брандмауэрами и NAT. Современные протоколы, такие как `HTTP/HTTPS`, работают через стандартные порты (80 и 443), что упрощает настройку сетевой безопасности. 
3. **Удобство использования**: Современные протоколы, такие как `HTTP/HTTPS`, поддерживают более удобные интерфейсы и API для работы с файлами. Например, RESTful API позволяет легко интегрировать загрузку и скачивание файлов в веб-приложения.
